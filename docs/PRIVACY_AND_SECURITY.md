# 隐私与安全

## 数据原则

- 默认本地、默认最小权限、默认不训练、默认不跨服务发送。
- 只处理用户本人有权处理的数据。
- 第三方聊天、好友关系、群聊和评论采用最小化、脱敏和访问限制。
- 密码、Cookie、验证码、API Key、支付信息和完整身份凭证永不进入证据或记忆。
- 用户可逐连接器选择本地导出、官方 API/OAuth 或浏览器辅助模式；浏览器模式只临时使用现有会话，不导出或持久化 Cookie。
- 用户可选择仅本人内容或全部获授权内容；后者必须保留发言者归属，第三方内容不得归因给用户。
- “永久保存”改为“在明确保留期限内持久保存，直到用户删除或授权失效”。

## 威胁模型

- 本机被他人访问。
- 数据库、备份或导出文件泄露。
- OAuth 令牌泄露或被过度授权。
- 恶意网页/文档通过提示注入影响抽取器。
- 模型错误归属、编造事实或泄露敏感推断。
- 连接器失效，系统继续使用过期数据。
- 删除来源后派生摘要仍然存在。

## M0 控制

- 无网络依赖。
- SQLite 外键级联和人工删除确认。
- 审计不保存证据正文。
- 画像只读取已确认且证据有效的声明。
- 高敏感结论必须人工确认。

## M0 已知缺口

- 数据库正文未加密。
- 没有数据库签名或防篡改。
- 没有独立安全审计。
- 没有自动保留期限执行。
- 没有连接器、令牌管理、备份恢复和密钥轮换。
- 审计日志可被本机管理员修改。

因此 M0 只适合受控原型，不应存放高敏感数据。

## 合规检查

在中国部署时至少评估《个人信息保护法》《数据安全法》和《网络安全法》要求，包括目的限制、最小必要、敏感个人信息、单独同意、删除权、跨境传输和自动化决策。其他司法辖区还需评估 GDPR 等规则。本文不是法律意见。

## 连接器准入清单

- 是否有官方 API 或合法数据导出？
- 权限是否可限制为只读？
- 是否明确告知用途、保留期限和撤回方式？
- 能否增量同步和响应删除信号？
- 是否涉及第三方个人数据？
- 是否包含敏感个人信息？
- 令牌是否存于系统密钥链？
- 平台停服、API 变更和授权撤销时如何降级？
