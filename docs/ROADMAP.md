# 实施路径

后续建设按 [跨平台与多模态整合设计](MULTISOURCE_DESIGN.md) 推进，优先补齐稳定内容身份、行为观察和媒体证据，再做跨来源总结与长期画像。

## M0：本地证据账本（当前）

已实现：

- 来源授权登记、撤销和删除。
- 原始证据写入、哈希和元数据。
- 事实/推断声明、支持/反对证据关系。
- 人工确认、冲突拦截和审计。
- 已确认画像的 JSON/Markdown 导出。

退出条件：本地闭环可运行，关键删除和撤销路径有测试。

## M1：个人可用

当前进展：已完成本地文件连接器、ChatGPT/抖音/通用 JSON/文本导入、内容哈希去重、前台轮询，以及可扩展的访问模式和内容范围授权模型。

- 引入 SQLCipher 或等价加密。
- 增加交互式复核界面。
- 增加 Markdown/JSON 批量导入、幂等去重和导入报告。
- 增加按来源、声明和时间窗口删除。
- 增加加密备份、恢复和 schema 迁移。
- 将示例 Skill 接入已确认画像检索。

退出条件：真实个人数据可在受控环境中持续使用；删除和备份经过演练。

## M2：首个稳定连接器

- 选择一个仅需只读权限、API 稳定的来源。
- 实现 OAuth/令牌存储、增量游标、重试、限流和健康检查。
- 保留原始对象 ID、更新时间和删除信号。
- 连接器不直接生成事实，只把数据送入证据层。

退出条件：断网、令牌过期、平台限流和撤销授权都有明确恢复路径。

## M3：候选事实抽取

- 建立人工标注集，覆盖自称事实、偏好、关系、时间状态和反例。
- LLM 抽取器在隔离环境中运行，只输出候选声明和证据定位。
- 增加发言者归属、时间归一化、实体消歧和冲突检测。
- 所有候选默认 `pending`，敏感类型进入单独审核队列。

退出条件：错误归属、无证据声明和错误记忆达到预设门槛。

## M4：检索与 Codex 集成

- 提供只读 retrieval API 或 CLI 查询。
- 通过 Skill 在用户明确请求时检索最小必要上下文。
- 返回声明、来源、时间、敏感级别和不确定性。
- 禁止模型把推断自动升级为事实或用于高影响决策。

退出条件：任务上下文相关性提升，同时错误记忆率和隐私暴露面可测。

## M5：多来源长期运行

- 建立连接器版本矩阵、数据源健康面板和迁移机制。
- 增加策略引擎、用途限制、保留期限自动执行和审计导出。
- 定期评估来源质量、画像漂移、冲突和过时信息。
- 在多用户或商业部署前完成法律、隐私和安全审查。

## 推荐优先级

1. 加密、复核和删除体验。
2. 稳定一个推荐流连接器，同时接入一种主动意图来源。
3. 带证据定位的抽取器。
4. 检索质量与校准。
5. 主动分享补充桌面/手机内容，再扩展持续采集的多端覆盖。

不要从“接入最多平台”开始。最容易导致项目失败的是无证据画像、删除不彻底和连接器静默失效，而不是来源数量不足。

## 长期来源策略与阶段验收（2026-11-02）

以下为后续规划，不代表已实现。它与 M0–M5 的治理、检索及安全建设并行；不因等待全平台接入而推迟来源偏差验证。

| 阶段 | 建设重点 | 验收标准 |
|---|---|---|
| A：推荐流与主动意图 | 完善一个高使用时长推荐流平台的内容 ID、音画、行为对齐；同时接入 AI 对话或主动搜索后的阅读记录 | 能区分推荐曝光与主动查询、作者观点与用户陈述；比较加入第二类来源前后的结论变化 |
| B：跨应用主动分享 | 提供“分享给资料库”或选择导入入口，接收微信、QQ、手机的指定内容；按格式补充图片、录音等处理 | 导入时保留来源、发言者、时间与分享目的；不能将第三方内容归为用户事实；没有自动读取整个聊天库 |
| C：桌面伴随采集 | 在代表性应用版本中验证可访问界面与截图/OCR；逐应用开放持续采集 | 明确支持范围、采集状态与漏采；暂停/撤销有效；在读取能力不足时明确降级而非假装完整 |
| D：手机与长期整合 | 增加手机授权采集、跨设备同步和长期主题分析 | 处理权限变化、中断、重复内容和时间差；原始来源撤销传播至派生内容；各端覆盖缺口可见 |

平台排序同时考虑用户实际使用频率、信息独特性、主动意图强度、当前画像缺口、技术可维护性和处理成本；不只依据时长。阶段 A 优先推荐流、搜索/长文、AI 对话；阶段 B 补社交背景与现实任务；微信/QQ 的全自动持续采集及手机全覆盖放在 C/D。

每阶段以固定评估样例和用户纠正验证：临时兴趣是否被误判为长期目标、多人发言归属是否正确、重复转载是否被重复计权、跨来源矛盾是否保留、缺少来源时是否明确表示未知。评估指标记录错误率、证据可追溯性、纠正后更新情况及采集成功/中断情况，不宣称整体人格可被完整测量。

## 三条主线与技术路线

以下为计划，验收条件尚未达成。三条主线贯穿 M1–M5，并沿用阶段 A–D 的来源策略。

### 1. 持续运行（M1–M2，M5 扩展）

- 沿用 Windows 启动入口、浏览器扩展和本机接收端。先实现登录后恢复与本地待处理队列；事件持久化后再确认接收，用稳定事件 ID 去重，断网或重启后重试。采集与 Agent 分析分开运行，分析失败时保留待处理任务。
- 区分暂停、无新活动、采集器离线和处理失败。暂停后停止新采集；撤销后阻止该来源的排队任务继续处理。
- 验收：用一个真实连接器连续运行一周，演练浏览器关闭、接收端重启和暂停；检查已入队事件可恢复、重试不重复入库，未覆盖时段可见。

### 2. 跨来源理解（M3–M4，依赖可重复的采集输入）

- 第一轮用浏览行为与主动分享的学习记录。保留时间、发言者、行为类型、父证据；同内容转载去重，但保留各次独立观察。按主题和时间找候选证据，让 Agent 输出带引用的新增、修订或冲突项。
- 把推荐曝光、主动行为、自述和实际表现分开。模型自动提出修订，人工决定是否确认；按任务召回仍有证据支持的已确认条目。撤销来源时重新检查受影响的条目。
- 验收：同一学习任务比较单来源与双来源结果。覆盖推荐曝光误判、第三方发言归属、旧判断被新证据修订三个案例；新会话应采用已确认的修订，并能追溯依据。

### 3. 多模态（先用显式分享验证，后接连续采集）

- 先支持主动分享的图片和短音频，分别做本地 OCR 和转写。派生记录保留父证据、处理版本、图像区域或音频时间段；读取时标明实际处理过的模态与缺失项。
- 视频先用明确内容 ID 和播放器时间对齐行为记录，再逐步接入授权音画片段。个人外貌用明确指定的图像作为独立来源，单独授权和召回，不从图像推断人格或认知水平。
- 验收：用授权样本定位识别结果对应的原图区域或音频片段。删除样本后，相关派生结果停止被召回，并检查原件、缓存与派生副本的清理范围。

首个联合里程碑：一条真实采集链路能恢复运行，两类来源能推动一次学习画像修订，修订在新会话中生效。显式分享的多模态样本可并行验证，验收后再纳入连续采集。
