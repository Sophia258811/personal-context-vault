# 实施路径

后续建设按 [跨平台与多模态整合设计](MULTISOURCE_DESIGN.md) 推进，优先补齐稳定内容身份、行为观察和媒体证据，再做跨来源总结与长期画像。

## M0：本地证据账本（当前）

已实现：

- 来源授权登记、撤销和删除。
- 原始证据写入、哈希和元数据。
- 事实/推断声明、支持/反对证据关系。
- 人工确认、冲突拦截和审计。
- 已确认画像的 JSON/Markdown 导出。

退出条件：本地闭环可运行，关键删除和撤销路径有测试。

## M1：个人可用

当前进展：已完成本地文件连接器、ChatGPT/抖音/通用 JSON/文本导入、内容哈希去重、前台轮询，以及可扩展的访问模式和内容范围授权模型。

- 引入 SQLCipher 或等价加密。
- 增加交互式复核界面。
- 增加 Markdown/JSON 批量导入、幂等去重和导入报告。
- 增加按来源、声明和时间窗口删除。
- 增加加密备份、恢复和 schema 迁移。
- 将示例 Skill 接入已确认画像检索。

退出条件：真实个人数据可在受控环境中持续使用；删除和备份经过演练。

## M2：首个稳定连接器

- 选择一个仅需只读权限、API 稳定的来源。
- 实现 OAuth/令牌存储、增量游标、重试、限流和健康检查。
- 保留原始对象 ID、更新时间和删除信号。
- 连接器不直接生成事实，只把数据送入证据层。

退出条件：断网、令牌过期、平台限流和撤销授权都有明确恢复路径。

## M3：候选事实抽取

- 建立人工标注集，覆盖自称事实、偏好、关系、时间状态和反例。
- LLM 抽取器在隔离环境中运行，只输出候选声明和证据定位。
- 增加发言者归属、时间归一化、实体消歧和冲突检测。
- 所有候选默认 `pending`，敏感类型进入单独审核队列。

退出条件：错误归属、无证据声明和错误记忆达到预设门槛。

## M4：检索与 Codex 集成

- 提供只读 retrieval API 或 CLI 查询。
- 通过 Skill 在用户明确请求时检索最小必要上下文。
- 返回声明、来源、时间、敏感级别和不确定性。
- 禁止模型把推断自动升级为事实或用于高影响决策。

退出条件：任务上下文相关性提升，同时错误记忆率和隐私暴露面可测。

## M5：多来源长期运行

- 建立连接器版本矩阵、数据源健康面板和迁移机制。
- 增加策略引擎、用途限制、保留期限自动执行和审计导出。
- 定期评估来源质量、画像漂移、冲突和过时信息。
- 在多用户或商业部署前完成法律、隐私和安全审查。

## 推荐优先级

1. 加密、复核和删除体验。
2. 单一稳定连接器。
3. 带证据定位的抽取器。
4. 检索质量与校准。
5. 多平台覆盖。

不要从“接入最多平台”开始。最容易导致项目失败的是无证据画像、删除不彻底和连接器静默失效，而不是来源数量不足。
