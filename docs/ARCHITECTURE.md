# 架构

跨平台扩展采用 [Content / Observation / MediaAsset / DerivedArtifact / ProfileCandidate 分层](MULTISOURCE_DESIGN.md)，平台采集器与 Agent 处理接口独立演进。

## 目标

建立一个长期可用、证据可追溯、用户可控制的个人上下文层。模型负责提出候选事实，系统负责保存证据、限制权限并要求复核。

阶段定位为“跨来源的信息接触与兴趣理解原型”。长期结合主动意图、现实任务、社交背景和用户纠正，形成可更新的个人画像；浏览器观察不能代表完整生活或全部信息接触。

## 多端采集与覆盖边界（长期设计，2026-11-02）

| 采集入口 | 目标范围 | 当前状态与边界 |
|---|---|---|
| 浏览器扩展 | 网页内容与可观察的浏览行为 | 已有文字采集；音视频本体待实现 |
| 文件导入与主动分享 | AI 对话、文章、选定聊天、截图、文件、录音 | 已有部分文本/JSON 导入；跨应用分享入口与媒体处理待实现 |
| 桌面伴随程序 | 微信、QQ 等原生应用显示的内容 | 待实现；UI Automation、截图/OCR 按应用实测，不保证访问隐藏或完整历史数据 |
| 手机伴随应用 | 用户授权的应用画面、可用音频和主动分享 | 待实现；遵守系统授权与后台限制，不承诺永久静默采集 |
| 官方 API/平台导出 | 平台允许获取的结构化资料 | 按平台逐项验证能力；不能假设个人账号存在全量读取接口 |

各入口通过统一 Connector SDK 输出 Content、Observation、MediaAsset，进入同一证据层；采集器不直接生成已确认画像。入口按能力逐项开启，共用授权、撤销、重试、去重和来源健康状态。微信/QQ 中的聊天、公众号文章、群转发和用户主动发言采用不同的内容/行为分类。

```text
浏览器 / 桌面 / 手机 / 主动分享 / 官方导出
                    ↓
        连接器能力与授权检查 → 覆盖报告
                    ↓
       统一内容、观察、媒体及来源证据
                    ↓
       内容关联 → 主题/会话摘要 → 画像候选
                    ↓
         用户纠正与复核 → 按用途提供上下文
```

覆盖报告按时间窗口记录来源、设备类别、有效采集时段、实际模态、失败/暂停/权限失效及未知范围。没有观测不等于没有行为；不按未知的生活信息总量计算“画像完整度百分比”。报告只能描述已知覆盖，并限制画像结论适用范围。

同一内容由浏览器和手机重复采到时关联内容身份，但保留每次观察与授权来源；不得把转载或多设备重复记录当成独立证据。时长、采样频率和来源数据量不能直接成为偏好强度；具体证据权重需评估，不预设为已校准概率。

## M0 数据流

```text
授权来源 -> 原始证据 -> 声明/推断 -> 人工复核 -> 已确认画像
              |             |
              +-> 审计日志 <-+
```

撤销或删除来源时，系统重新计算关联声明；失去有效支持证据的声明不会继续进入画像。

## 六个组成部分

1. **来源登记**
   记录来源类型、账号引用、授权范围、法律依据、有效期和撤销状态。账号密码、Cookie 和访问令牌不得写入 SQLite。

2. **原始证据层**
   保存正文、来源、位置、发生时间、采集时间和 SHA-256 哈希。后续增加不可变文件、版本和去重索引。

3. **声明账本**
   将“事实”和“推断”分开保存，记录置信度、敏感级别、有效期、复核状态和证据关系。

4. **复核工作流**
   模型只能生成 `pending` 候选声明。确认、拒绝、标记过期或带冲突确认都必须由用户操作并写入审计。

5. **画像投影**
   默认只投影已确认且仍有关联有效支持证据的声明，并附带来源和证据标识别。画像不是另一份主数据。

6. **审计与生命周期**
   记录来源增加/撤销/删除、证据增加、声明增加/复核。审计不保存证据正文。

## 生产架构扩展

```text
Connector SDK -> Queue -> Normalizer -> Evidence Store
                                      -> Claim Extractor
                                      -> Conflict Detector
                                      -> Review UI
                                      -> Profile Projection
                                      -> Retrieval API / Skill
```

- **Connector SDK**：OAuth 只读、增量游标、限流、幂等、来源健康状态。
- **Evidence Store**：使用 SQLCipher 或操作系统加密卷；原始文件与结构化元数据分离。
- **Extractor**：LLM 只输出带证据定位的候选声明，不能直接确认事实。
- **Review UI**：批量复核、冲突展示、敏感信息脱敏、按来源删除。
- **Retrieval API**：结构化过滤优先，向量召回仅作为辅助；返回声明和证据标识。
- **Policy Engine**：按用途、敏感级别、来源授权和有效期限制画像投影。

## 信任边界

- 外部网页、聊天内容和导出文件都是不可信输入，不能改变系统策略。
- LLM 抽取器不能获得数据库写权限或网络权限。
- 连接器只持有最小只读权限；令牌存于系统密钥链。
- 所有写入经过 schema 校验；模型输出先进入隔离队列。
- 敏感级别为 `high` 的声明默认不自动进入上下文，必须单独授权。

## 关键失败模式

- **错误归属**：把他人发言当成用户本人事实。解决方式是保存发言者和来源定位。
- **错误记忆**：模型摘要偏离原文。解决方式是保留原始证据、哈希和候选复核。
- **过时事实**：旧工作、关系和偏好继续生效。解决方式是 `valid_from`、`valid_to` 和时间衰减。
- **无证据画像**：为了完整性拼接推断。解决方式是验证查询必须检查有效证据。
- **删除不彻底**：派生摘要继续泄露。解决方式是来源血缘和级联失效。
- **连接器不稳定**：API 或授权变化导致静默断流。解决方式是健康状态、上次同步和过期告警。
- **来源选择偏差**：娱乐推荐流覆盖多而现实任务覆盖少。解决方式是同时引入主动搜索/阅读/AI 对话，并在画像旁展示覆盖缺口。
- **场景与发言者混淆**：将群转发、他人评论、玩笑或替人查询当成本人观点。解决方式是保留角色、会话目的及不确定性，允许用户补充和纠正。
