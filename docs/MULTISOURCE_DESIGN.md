# 跨平台、多来源、多模态整合

目标：理解用户长期接触的信息、主动行为与变化。单个平台快照只是输入之一；信息源覆盖度、缺失项和证据来源必须同时可见。

## 统一对象

- Content：平台命名空间、稳定内容 ID、作者、正文、发布时间、内容版本。首页 URL 和标题不能代替稳定 ID。
- Observation：用户何时、在哪个来源、以何种方式接触内容。区分推荐曝光、搜索、打开、播放、暂停、收藏、评论、主动创作；页面上的搜索建议不能当成用户搜索。
- MediaAsset：图片、视频帧、音频分段、字幕，附媒体时间区间、采集方法、内容哈希和来源授权。只登记实际成功保存的媒体。
- DerivedArtifact：OCR、转写、内容摘要、跨来源主题摘要，记录父证据、模型/Agent、处理版本、缺失项和时间定位。
- ProfileCandidate：从用户行为或直接陈述提出的候选结论，附支持与反对证据、有效期、待确认状态。
- CoverageReport（规划）：按窗口描述来源、设备类别、已知有效采集时段、实际模态、暂停/失败/未知范围及可支持的结论范围。不能把未接入的手机、聊天或线下活动解释为不存在。

## 整合规则

1. 稳定内容 ID 相同的多个观察合并到一个内容组；播放进度、评论展开和观看时间点仍是独立观察，不丢弃原始证据。
2. 评论是独立第三方内容，与视频通过 comment_on 关联。作者陈述、平台摘要和用户发言分别标注。
3. 跨平台转载先形成 possible_same_content 关联，不能仅凭语义接近自动覆盖或合并。多个转载不能计算成多个独立支持来源。
4. 跨来源主题摘要保留所有父证据与授权范围；只在授权交集内对外提供。父来源撤销、删除或过期后重新计算派生内容。
5. 主题、会话、事件和长期趋势分别汇总；画像层保留时间变化与矛盾，不能把一次曝光固化为永久偏好。
6. 覆盖报告显示采集成功/失败、文本/画面/声音实际可用情况；不声称完整读取未加载内容。
7. 跨端内容进入统一证据模型，但保留设备、采集方法、发言者与会话目的；多次采样和多端转载不自动增加观点支持强度。
8. 推荐曝光、朋友转发、用户主动搜索与本人表达分别建模。优先补充能解释意图的来源；不能用娱乐时长替代现实目标，也不能从无记录推出无兴趣。

多端入口及能力边界见 [架构](ARCHITECTURE.md#多端采集与覆盖边界长期设计2026-11-02)，建设顺序与验收见 [长期路线图](ROADMAP.md)。覆盖报告、跨端关联和偏差评估尚待实现。

## 实现顺序与验收

1. 平台适配器提取稳定内容 ID 和区域类型；通用 DOM 为降级入口。测试同一视频进度变化归为一个内容组、不同视频不误合并。
2. 标签页媒体分段、帧与音轨时间对齐；为中断、权限失效、受保护内容提供明确状态。
3. Agent 任务按实际输入能力分发，返回来源定位、摘要和缺失项；文本模型不得声称识别过视频。
4. 跨来源内容图与会话摘要；验证转载去重、冲突保留和来源撤销传播。
5. 多时间窗口画像候选与人工纠正；验证事实归属、支持/反对证据、有效期。

## 当前实现边界

pcv/integration.py 提供保守整合函数与数据库查询：同一授权来源和平台的稳定内容 ID 分组，保留各次观察。已接入新浏览器事件的文件导入结果，无需修改历史证据。

浏览器扩展 0.3.0 从抖音 video 路径、modal_id 或可见播放器祖先的明确 ID 属性识别内容；支持 YouTube watch/shorts ID 和 Bilibili BV/av 分 P ID。不读取其他推荐卡片来猜当前视频。无法识别时保留 unresolved，旧首页快照不反推 ID。

事件 v2 包含 body/comments/navigation/unclassified 分区、客户端采样时间与播放器 currentTime/duration/paused/playbackRate。接收端验证域名、ID、字段长度和有限数值。分区依赖 DOM 启发式，多个可见播放器不任选其一；媒体状态不代表已下载音轨或画面。

只读整合查询（来源 ID 换成实际值）：

```powershell
python -m pcv.integration --source 4
python -m pcv.integration --source 4 --output .pcv/integrated/browser.json
```

无 output 时只输出数量；导出的详情含私人内容。查询排除撤销或过期来源，不删除原始观察。导出文件本身不自动撤回。

语义匹配、媒体本体采集、跨来源主题摘要和派生删除传播仍待实现。新适配器已通过合成测试，尚待真实站点验收。
