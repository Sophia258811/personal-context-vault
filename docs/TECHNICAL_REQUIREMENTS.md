# 技术需求

## P0：可信闭环

| 领域 | 需求 | 验收标准 |
|---|---|---|
| 数据模型 | 来源、证据、声明、证据关系、审计分表 | 每条画像声明可追溯到来源和证据 |
| 授权 | 来源必须登记 scope、依据、有效期和撤销状态 | 无 active source 不能新增证据 |
| 认知分层 | 事实、观察、推断、偏好、关系、特质分型 | 画像中类型不混淆 |
| 复核 | 候选声明默认 pending | 未确认声明不进入默认画像 |
| 冲突 | 支持和反对证据都能关联 | 有反对证据时禁止静默确认 |
| 生命周期 | 撤销、删除、过期、级联失效 | 删除来源后孤立声明转 needs_review |
| 审计 | 记录管理操作但不记录正文和凭证 | 审计日志搜索不到证据正文 |
| 本地优先 | 默认无网络、单用户、本地数据库 | 断网可完成全流程 |

## P1：个人可用

| 领域 | 需求 |
|---|---|
| 加密 | SQLCipher 或等价方案加密正文；密钥进入系统密钥链 |
| 导入 | Markdown/JSON/CSV 导入器，幂等去重，来源游标 |
| 复核 | 本地 TUI 或 Web UI，支持批量确认、拒绝、脱敏和冲突处理 |
| 检索 | 按类型、敏感级别、有效期和来源过滤；只返回最小必要画像 |
| 备份 | 加密备份、恢复演练、schema 迁移和完整性检查 |
| 删除 | 按来源、声明、时间窗口删除；删除任务可验证完成 |
| Skill | Codex Skill 只读取已确认画像，明确要求引用不确定性 |

## P2：连接器与自动化

| 领域 | 需求 |
|---|---|
| Connector SDK | OAuth 只读、refresh token、增量游标、限流、重试、撤销 |
| 数据源 | 先接本人导出文件，再逐个接官方 API；不依赖凭证共享或违规抓取 |
| 提取 | LLM 生成候选声明，必须带证据 ID、原文定位和抽取版本 |
| 归一化 | 去重、语言统一、日期标准化、实体消歧、发言者归属 |
| 冲突检测 | 同主体同谓词不同值、时间冲突、来源可信度差异 |
| 可观测性 | 连接器健康、同步延迟、失败率、过期授权和抽取质量指标 |
| 策略 | 按用途和授权范围检索；敏感特质和第三方信息默认排除 |

## 事实校验

- 来源层级：本人确认 > 原始直接陈述 > 原始观察记录 > 多次独立证据 > 单条平台内容 > 模型推断。
- 平台推荐内容不能直接视为用户兴趣；必须记录 `feed/recommendation` 来源类型。
- 对高影响或高敏感结论，要求本人确认；不自动推断健康、金融、政治、宗教、性取向、精确位置等属性。
- 低置信度、冲突和过期信息必须可见，不能用单一分数掩盖不确定性。
- 置信度需要基于标注数据校准；M0 的人工填写值不代表统计概率。

## 质量指标

- 画像声明证据完整率：100%。
- 直接事实/推断分离率：100%。
- 来源撤销后的权限传播延迟：P1 目标小于 5 分钟。
- 删除任务成功率：100%，失败必须告警并可重试。
- 抽取评估：使用人工标注集衡量错误归属、错误记忆、冲突遗漏和校准误差。

## 非功能需求

- Python 3.11+；无外部依赖的 M0。
- SQLite schema 带版本号和迁移测试。
- 所有命令错误必须为非零退出码，并且不写入半个事务。
- 单元测试控制在关键路径和危险边界，不堆叠穷举矩阵。
- 日志不得包含密钥、令牌、Cookie、证据正文和完整私人声明。
